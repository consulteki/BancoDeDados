# Orientação — Módulo 17

A entrega deve provar, não apenas afirmar:

- Compose saudável e logs da API;
- testes repetíveis sem depender da base pessoal;
- falha da CI quando um erro é introduzido;
- OpenAPI compatível com respostas reais;
- backup restaurado e contagens verificadas;
- ausência de `.env` e senhas no histórico;
- usuário da API sem privilégios DDL;
- logs sem dados sensíveis.

RPO é a perda de dados aceitável medida no tempo; RTO é o tempo aceitável para restaurar o serviço. Ambos devem ser definidos pelo negócio, não pela ferramenta.
